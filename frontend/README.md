# Taskspace — frontend

React 19 + Vite 8 + Tailwind CSS v4, plain JSX. UI only: everything on screen is
generated by `src/data/seed.js` at start-up, no request is ever made, and a
reload resets the app.

```bash
npm install
npm run dev
```

See the [root README](../README.md) for what the app does and
[CLAUDE.md](../CLAUDE.md) for the traps worth knowing before you edit.

## Structure

| Path | |
| --- | --- |
| `src/data/seed.js` | Members, workspaces, statuses, labels and the generated tasks, files, comments and conversations. |
| `src/state/AppProvider.jsx` | The whole app state plus every action that changes it. |
| `src/lib/select.js` | Read-only derivations: filtered tasks, counts, workspace summaries, file lists. |
| `src/lib/config.js` | Accent, density and default view — the design's editor props as constants. |
| `src/lib/text.js`, `src/lib/mentions.js` | `@mention` / `/TSK-104` parsing and autocomplete rows. |
| `src/components/ui/` | Avatar, StatusDot, SearchField, Dialog — the pieces used across screens. |
| `src/index.css` | Design tokens under Tailwind v4 `@theme`. |

## How state is organised

`useApp()` returns `{ state, actions }`. One provider holds the state; actions
are grouped by area and always update it immutably.

Anything derived is a function in `src/lib/select.js` rather than a field in the
store, and **transient UI state stays local to the component that owns it** — the
open filter dropdown, the colour picker, a comment draft. Only state two distant
components share is worth putting in the provider.

Screens switch on `state.screen` in `src/App.jsx`. There is no router, so a
screen is not a URL.

`revealTask()` is the one action that crosses everything: a `/TSK-104` reference
in a comment, a chat message or a search result opens that task, switching
workspace if it lives in another one. `RichText.jsx` only links references that
resolve to a real task, so a typo renders as plain text.

## Design notes

Tokens are `@theme` entries in `src/index.css`. The palette is one ink colour
used at many opacities — `border-ink/9`, `text-ink/55` — plus a dark shell for the
sidebar and login panel. Write new hairlines and muted labels that way rather
than adding tokens for them.

Status colours are not theme tokens. They belong to the workspace and are edited
at runtime in settings, so they travel through state and land on elements as
inline styles.

Icons are literal glyph characters (`⌕ ✕ ⇄ ⌄ ⠿ ◫ ◌ ✉ ＋`), matching the design.
There is no icon library.

## Two Tailwind v4 rules to keep

`font-500` and `font-600` compile to nothing — use `font-medium` and
`font-semibold`. And base CSS belongs inside `@layer base`: unlayered rules
outrank every utility no matter the specificity, which is how a stray
`button { color: inherit }` turns `text-white` on a dark button into invisible
text. `:focus-visible` is the one rule deliberately left unlayered.
